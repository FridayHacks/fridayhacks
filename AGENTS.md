# FridayHacks contributor instructions

## Company Knowledge Base

At the start of every session, before working on this project, read:

1. `~/Dev/swt/semakb/00-Index/Home.md` - company and project overview
2. `~/Dev/swt/semakb/00-Index/Media.md` - Media category context
3. `~/Dev/swt/semakb/02-Divisions/Media/fridayhacks/Overview.md` - FridayHacks context
4. `~/Dev/swt/semakb/02-Divisions/Media/fridayhacks/Architecture.md` - project architecture

Before making technical decisions, check `~/Dev/swt/semakb/03-Decisions/` for applicable ADRs. Record durable discoveries and decisions in the relevant Semakb notes when completing work.

## Project Guide

Read `CLAUDE.md` for project structure, writing conventions, development commands, and contribution guidance before making changes.

## Blog Post Style

Never use emojis or em dashes in blog posts, including titles, descriptions, headings, and body text. Use regular hyphens or rewrite sentences instead of using em dashes.

## Required Updates

For every change, including blog posts, code, configuration, and contributor rules, always update the relevant documentation, `CHANGELOG.md`, and `VERSION` before considering the work complete. Use semantic versioning (major for breaking changes, minor for new functionality, patch for fixes and documentation changes), and keep the changelog's release version consistent with `VERSION`.
